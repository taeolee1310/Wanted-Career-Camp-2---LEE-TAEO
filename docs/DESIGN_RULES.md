# 디자인 규칙

기준 문서는 `DESIGN-apple.md`이고, 값의 원천은 `design/tokens.json`입니다. `css/style.css`의 `:root` 변수는 이 값과 같게 유지합니다. 4개 페이지(메인·캠프소개·일정표·오시는 길)가 모두 같은 `css/style.css`를 씁니다. `location/css/location.css`에는 오시는 길 고유 레이아웃만 둡니다.

## 1. 정보 계층 (제목 레벨 = 시각 레벨)

| 레벨 | 태그 | 용도 | 토큰 |
| --- | --- | --- | --- |
| L0 | `nav` | 글로벌 내비 (44px 블랙 바) | 12px / 400 |
| L1 | `h1` | 페이지 제목 (페이지당 1개) | `--fs-display` 34–64px / 600 |
| L2 | `h2` | 섹션 제목 | `--fs-title` 28–40px / 600 |
| L3 | `h3` | 카드·패널 제목 | `--fs-subtitle` 21px / 600 |
| 리드 | `p.lead` | 제목 바로 아래 한 문장 | `--fs-lead` 19–28px / 400 |
| 본문 | `p` | 기본 문단 | `--fs-body` 17px / 400 |
| 캡션 | `small`, 보조 설명 | 설명·메타 | `--fs-caption` 15px |
| 고지 | 푸터 | 법적·고지 문구 | `--fs-fine` 13px |

- 제목은 레벨을 건너뛰지 않습니다 (h1 → h2 → h3). 크기만 맞추려고 레벨을 바꾸지 않습니다.
- 굵기는 300·400·600만 씁니다 (500 금지).
- 섹션은 한 화면 묶음(타일)이고, 타일 안의 정보는 카드 → 표 → 목록 순으로 밀도가 높아집니다.

## 2. 상단 메뉴 (모든 페이지 동일)

- 높이 44px, 최대 폭 1240px, 좌우 24px 여백을 모든 페이지에서 같게 씁니다. 헤더는 `js/render.js`가 한 곳에서 그립니다.
- 순서는 로고 → 메인화면 · 캠프소개 · 일정표 · 오시는 길 → 다크/라이트 토글(우측 끝).
- 현재 페이지는 흰색으로 표시합니다(`aria-current="page"`). 페이지가 바뀌어도 크기·간격은 바뀌지 않습니다.
- 세로 스크롤바 유무에 따라 가로 위치가 밀리지 않도록 `html { overflow-y: scroll }`을 씁니다.
- 833px 이하에서는 메뉴 링크만 햄버거로 접히고, 토글은 그대로 보입니다.

## 3. 다크·라이트

- 색은 의미 변수(`--bg`, `--bg-alt`, `--surface`, `--ink`, `--muted`, `--hairline`, `--link`)로만 씁니다. 컴포넌트에 색상 코드를 직접 쓰지 않습니다.
- `<html data-theme="light|dark">`로 전환합니다. 저장된 선택이 없으면 시스템 설정을 따르고, 선택은 `localStorage`의 `theme`에 저장합니다.
- `js/theme.js`는 `<head>`에서 먼저 실행해 첫 화면 깜빡임을 막습니다.
- 어두운 타일(`--tile`)과 글로벌 내비(검정)는 두 모드에서 모두 어둡게 유지합니다.
- 본문 보조 글자색은 대비를 위해 라이트 `#6e6e73`, 다크 `#98989d`를 씁니다 (`DESIGN-apple.md`의 #7a7a7a는 흰 바탕에서 4.5:1에 못 미침).

## 4. 시각 규칙

| 항목 | 규칙 |
| --- | --- |
| 타일 | 흰색 · 파치먼트 · 니어블랙이 번갈아 나옴. 색 변화가 섹션 구분선 |
| 포인트 | Action Blue(#0066cc) 하나만. 어두운 면 링크는 #2997ff |
| 버튼 | 블루 pill(패딩 11×22), 보조는 고스트 pill. 눌림 `scale(0.95)` |
| 카드 | 18px 모서리, 1px 헤어라인, 패딩 24px. 그림자 없음 |
| 그림자 | 제품 렌더 자리인 로드맵 카드와 약도 이미지에만 `--product-shadow` |
| 그라데이션 | 사용하지 않음 |
| 간격 | 8px 기준, 섹션 상하 80px(모바일 48px) |
| 반응형 | phone ≤ 640 · tablet ≤ 833 · 1023 이하에서 4열 → 2열 |
| 접근성 | 터치 영역 44px 이상(아이콘 버튼 제외), 포커스 링 2px, 본문 대비 4.5:1 |

## 6. 가독성 기준 (2026-10 점검)

- 글자 최소 크기는 13px입니다. 본문 보조 설명은 15px, 줄 간격은 1.5 이상입니다.
- 일반 글자는 대비 4.5:1 이상, 24px 이상 큰 글자는 3:1 이상을 지킵니다. 4개 페이지를 라이트·다크로 측정해 미달 0건을 확인했습니다 (히어로 영상 위 글자는 제외).
- 보조 글자색: 라이트 `#636366`, 다크 `#98989d`. `DESIGN-apple.md`의 #7a7a7a는 흰 바탕에서 4.5:1에 못 미쳐 쓰지 않습니다.
- 파란색은 역할로 나눕니다. 글자·링크는 `--link-text`(라이트 #0066cc, 다크 #2997ff), 버튼 배경은 `--primary`(다크 #0068d4)이고 버튼 글자는 흰색입니다.
- 히어로 영상 위 글자는 검은 막(40%)과 약한 그림자로 대비를 확보합니다.

## 7. UX 라이팅

- 문장은 `~해요` 체로 통일합니다. 버튼과 라벨은 짧은 동사형("지원서 작성하기", "제출하기")으로 씁니다.
- 상태는 지금 사용자가 할 수 있는 일로 말합니다. 예: 마감 후에는 "지원 마감 날짜" 대신 "○○에 지원이 마감됐어요".
- 막힌 상황에는 이유를 먼저 알려 줍니다. 예: 마감 후에도 지원서가 열리는 이유를 팝업 상단에 안내.
- 섹션 제목은 사용자가 궁금해할 질문·이익으로 씁니다 ("캠프에서 받는 혜택", "꼭 알아야 할 날짜", "오시는 곳").

## 작업 규칙
- 화면 문구를 디자인에서 새로 쓰지 않습니다. 문구는 `content/`에서 가져옵니다.
- 새 색·간격 값이 필요하면 토큰을 먼저 추가하는 PR을 엽니다.
- hover 상태는 문서화하지 않고, 기본·눌림 상태만 정의합니다.
